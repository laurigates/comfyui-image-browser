# CLAUDE.md

ComfyUI custom-node pack with a thin Python backend (a node + HTTP endpoints in `image_browser.py`) and a TypeScript frontend extension built to `web/dist/` via bun. See ADR-0001.

## The pattern ("the vein")

A mobile-first ComfyUI usability pack in the *standalone-modal* vein: instead of intercepting a per-node widget, a frontend extension opens a STANDALONE modal from the app chrome — an action-bar button plus a command (palette/hotkey-bindable) and a menu entry. There are **no target widgets to hook**, so there is no `TARGET_WIDGETS` / `onPointerDown` wrapping. The modal is **touch-first** (16px inputs to avoid iOS zoom, big tap targets, momentum scroll); its primitives come from `@laurigates/comfy-modal-kit` (`openModalShell` / `fuzzyScore` / `notify` / `makeLauncher` / `ensureStyleOnce`, plus the in-dialog `openShellOverlay` / `confirmInShell` / `promptInShell` used for delete-confirm, rename, the move picker, and the metadata card — kept in-dialog, not a second `openModalShell`, so single-modal discipline doesn't close the browser), imported and inlined by `bun build` — not copied into the pack. `openShell()` is exported so the jsdom mount test can prove the modal body renders.

Concretely, this pack is a **full-canvas image browser + file manager**: the modal
fills the whole viewport (`width: 100vw; height: 100vh` on `.ib-dialog`), standing
in for the canvas while open. It reuses the card-grid file-explorer pattern proven
in `comfyui-gallery-loader`'s `image-picker` (breadcrumbs, thumbnail grid,
lazy-load, sort, fuzzy search), but as a standalone view that **manages** files
(delete / rename / move) rather than committing a value to a node widget. There is
**no custom node** — `NODE_CLASS_MAPPINGS` is intentionally empty; all value lives
in the HTTP endpoints + the served bundle.

## Endpoint surface (`/image_browser/`)

| Endpoint | Method | Purpose |
|---|---|---|
| `/base` | GET | ComfyUI well-known dirs (base/input/output/temp/user). Frontend hard-codes no paths. |
| `/list` | GET | Directory listing (`type=input\|output\|temp\|path`, `subfolder`/`path`, `extensions`, `kind`). **`kind=images\|videos`** narrows to one media family (the toolbar's segmented filter) by intersecting `KIND_FILTERS` into the extension set — it *composes* with `extensions=` rather than overriding it, applies **above** the recursive/non-recursive split and above the mtime sort + cap, and unlike `recursive` is **not** gated to the sandboxed roots (extension filtering costs nothing extra on `type=path`). An unrecognised `kind` narrows nothing rather than 400ing, since the request is still answerable. Placing it above the cap is the whole point: `kind=videos` returns the newest N *videos*, where a client-side filter would return the videos among the newest N files. Returns `{dirs, files}`; each file carries `mtime/size/width/height/ext`. With **`recursive=1`** (sandboxed roots only — ignored for `type=path`) it returns the **flat view**: every descendant file under `subfolder`, `dirs:[]`, each file tagged with a forward-slashed `subpath` relative to `subfolder` (`""` at the top level). Stops at `FLAT_LIST_CAP` files and sets `truncated:true`. The **non-recursive** path is capped too (`DIR_LIST_CAP`), through the same `_probe_newest` — both cap by mtime after sorting, never during the walk, so a truncated listing holds the newest N rather than whatever directory order reached first. Symlinked dirs are not followed. |
| `/thumb` | GET | Cached WebP thumbnail for **all** image listings — `?type=&subfolder=&name=` (sandboxed) or `?path=` (absolute). Served through the shared on-disk cache (`thumb_cache.py`) with ETag + long `max-age`; URLs embed `?v=<mtime>-<size>`. Never use core `/api/view` for thumbnails (it re-encodes every request, no cache headers). |
| `/metadata` | GET | Embedded generation metadata for one file — same dual addressing as `/thumb` (`?type=&subfolder=&name=` or `?path=`), same resolver (`_resolve_thumb_target`). Gated on **`METADATA_EXTS` before `os.path.isfile`** — every image, plus the video containers `image_meta` can read (MP4/MOV/M4V, WebM/MKV); **derived** from `image_meta.FORMAT_EXTS`, so `.avi`/`.mpg` (in `VIDEO_EXTS`, no reader) are excluded. Non-whitelisted extension → **400**, missing file → **404**. Returns `{format, source: comfyui\|a1111\|none, summary, raw, truncated}`: `format` is extension-derived (`""` for an image with no parser, e.g. `.gif` → 200 with empty metadata, never a 500); `summary` keys the parser could not read are **omitted, never guessed**; `raw` is every embedded text key verbatim, capped. Read-only, no cache headers (one-shot tap-to-open read). |
| `/file` | GET | Stream an absolute-path file (image/video), extension-gated. |
| `/delete` | POST | `{type, subfolder, name}` — delete a file. |
| `/rename` | POST | `{type, subfolder, name, new_name}` — rename in place. |
| `/move` | POST | `{type, subfolder, name, dest_type, dest_subfolder}` — move a **file** between roots/subfolders. |
| `/move_dir` | POST | `{type, subfolder, name, dest_type, dest_subfolder}` — move a **folder** (whole subtree) between roots/subfolders. Sandboxed types only; symlinked source rejected; refuses moving a folder into itself or a descendant (**400**). A same-named folder at the destination **merges** (`ok:true, merged:true`): contents move in, matching subfolders merge recursively, and any entry that would overwrite an existing file is left in the source and reported in `errors[]` (nothing is clobbered). A same-named *file* at the destination is still a hard **409**. |
| `/delete_many` | POST | `{items:[{type,subfolder,name},…]}` — batch delete; per-item errors in `errors[]`, partial success is still `ok:true`. |
| `/move_many` | POST | `{items:[…], dest_type, dest_subfolder}` — batch move into one destination; same per-item error contract. |
| `/rmdir` | POST | `{type, subfolder, name, recursive}` — delete a folder. Empty deletes outright; non-empty without `recursive:true` answers **409 with nested `{files, dirs}` counts** so the UI confirms with the real number before re-posting `recursive:true`. Sandboxed types only; symlinked dirs rejected. |
| `/mkdir` | POST | `{type, subfolder, name}` — create a folder under the current subfolder. Sandboxed types only; bare traversal-free name. A missing parent answers 404; an existing target (file or folder) answers **409** so the UI surfaces a name collision. |
| `/rating` | POST | `{type, subfolder, name, rating}` — persist a 0..5 star rating into the file's XMP (or sidecar). Sandboxed types only, like all writes. |
| `/ratings` | POST | `{items:[{type,subfolder,name}, …]}` — batch **READ** of ratings for the sidebar injector. Answers `{ok, ratings}` **index-aligned with `items`**. A per-item `null` (never `0`) means *could not read* — rejected address, missing file — because "unrated" and "unknown" must not look alike to a caller that paints stars. Capped at `MAX_RATING_BATCH` (200) so a client cannot ask the event loop to stat a whole output tree. Reads go through `xmp_meta.read_rating_cached`. Gated by `_resolve_sandboxed_file`, the same resolver the rating *write* uses — strictly laxer would do for a read, but ratings are a sandboxed-roots concept here and one perimeter is easier to keep correct than two. |

## File layout

| Path | Purpose |
|------|---------|
| `src/index.ts` | The extension: action-bar/command/menu launcher; exports `openShell()` → `openImageBrowser()`. |
| `src/browser.ts` | The full-canvas explorer — grid, tabs, breadcrumbs, sort/search, per-card delete/rename/move, the move-destination picker, and all CSS. |
| `src/api.ts` | Typed wrappers over the `/image_browser/*` endpoints + thumbnail/preview URL builders. No DOM. |
| `src/sidebar-stars.ts` | **One of two modules that touch stock ComfyUI UI** (see `src/lightbox-actions.ts` for the other). Injects a star row into the cards of ComfyUI's own *Media Assets* sidebar, behind the `ImageBrowser.SidebarStars` setting (default on; the settings store fires `onChange` once at registration, so the setting IS the lifecycle — there is no separate startup call to keep in sync). It is **not** a `comfyui-touch-shim` shim: shims paper over upstream *bugs* and carry a filed issue plus a death date, whereas this adds a capability the stock UI never had, and lives here because this pack already owns `/rating` and the XMP code. Three constraints keep it survivable, and all three are load-bearing: (1) **the grid is virtualized** — card DOM nodes are RECYCLED for different files as you scroll, so no state may be bound to a node; every pass re-reads the address off the card's own `<img>` and repaints from an address-keyed cache. The teardown-on-address-change guard exists for a **transient** window only (the steady state self-corrects via `applyStars` once the batch read lands) — its regression test therefore stalls the read and asserts *mid-flight*, because a settled-state assertion passes with the guard disabled (measured). (2) **Identity is the preview URL**, `/api/view?filename=&subfolder=&type=`, because at 1.47.x the card root has no `data-asset-id` (`main` has since added one) and the URL is the only identity present in both — conveniently already the address the rating endpoints take. (3) **Fail soft**: a rotted selector renders nothing; each pass is wrapped, mutations are coalesced (`SETTLE_MS`), and the click listener is delegated + capture-phase (the stock card stops propagation on its own root). The `CARD_SELECTOR` scoping is a cost/clarity choice, **not** the correctness guard — `cardRootOf()` is what actually keeps stars off canvas node previews and the lightbox (verified: the scoping test still passes with the selector widened to `"img"`). That exclusion still holds — the lightbox's bar comes from `lightbox-actions.ts`, which paints inside the lightbox dialog only; the two injectors never render into each other's territory. |
| `src/rating-cache.ts` | Address parsing (`parseAssetAddress`) + the **shared** address→rating cache both injectors read and write, extracted when the lightbox needed them too. Shared on purpose: rating in the lightbox must show on the card underneath once it closes. Keyed by file address, never by DOM node — see the recycling note above. |
| `src/lightbox-actions.ts` | **The second stock-UI injector.** Adds a star row + a delete button to `MediaLightbox.vue`, the full-screen viewer that *Inspect asset* opens (and that the Queue sidebar reuses), behind `ImageBrowser.LightboxActions` (default on, same onChange-is-the-lifecycle pattern). Verified identical in the shipped 1.47.10 bundle and 1.50.0 source: a Teleport-to-body `[role=dialog][aria-modal=true][data-mask]` whose own keydown handler maps ←/→ to navigation and Esc to close. **`data-mask` is the discriminator** — it is what separates the lightbox from every other dialog teleported to body. Four load-bearing constraints: (1) **one dialog element outlives many items** — navigating swaps the media `src` in place, so like a recycled card no state may be bound to the bar; a changed address REBUILDS it and blanks the stars to 0 rather than leaving the previous file's rating on the new image. That guard's test stalls the read and asserts mid-flight for the same reason the sidebar's does (measured: both fail with the guard removed). (2) **Navigation goes through the component's own key contract** (dispatch ArrowRight / Escape), never by clicking its buttons — those carry i18n'd aria-labels and utility-class icons, both of which move between versions. `hasMultipleItems()` reads the next-control's icon class, the most brittle thing here, and is deliberately fail-*single*: a rotted match closes the lightbox after a delete instead of advancing onto the file just deleted. (3) **The delete confirm swallows keydown in the capture phase** while up, so ←/→ cannot move to a different file between the question and the answer — otherwise the answer deletes the wrong one. It is a local overlay rather than the kit's `confirmInShell`, which needs a `ModalShellController` (`_onKey`) that does not exist here. (4) **The item list is the sidebar's prop and cannot be refreshed from here**, so a deleted file stays navigable; the module remembers it for the session and paints a plain "Deleted" notice instead of rateable stars. Unlike the sidebar's batch cache this one re-reads its single address on every navigation, so it is never stale. **Never widen the `/api/view` gate to `/api/viewvideo`** — that is the tempting one-liner for "videos get no bar" and it would delete the WRONG FILE. `AssetsSidebarTab.vue` builds each `ResultItemImpl` with `subfolder: ''` hard-coded and overrides only the `url` getter (to the asset's real `preview_url`), so `/api/view` carries the true subfolder while `ResultVideo`'s `vhsAdvancedPreviewUrl` is rebuilt from the discarded one. Measured live on 1.47.10: a `.webm` in `output/nsfw/2026-08-04/` → `/api/viewvideo?…&subfolder=` → **HTTP 204 empty** (the stock viewer shows a blank player — upstream bug), while the card's `/api/view` for the same file → 206. The `/api/view` restriction is the discriminator between "the asset's real address" and "an address rebuilt from state the frontend threw away"; there is a regression test asserting the refusal. |
| `src/comfyui-shims.d.ts` | Types the `/scripts/app.js` runtime import (via the `paths` mapping in `tsconfig.json`). |
| `__init__.py` | Loader stub. Imports (empty) node mappings from the backend module; exports `WEB_DIRECTORY = "./web/dist"`. |
| `image_browser.py` | HTTP endpoints only (no node). Bundled libs + stdlib only; reads gate on an extension whitelist, writes are sandboxed to input/output/temp. |
| `image_meta.py` | **Canonical home — edit it HERE.** `comfyui-gallery-loader` now vendors it (its `just sync-image-meta` + CI drift check pull from this repo's `main`), so a change here must be synced downstream. Note this is the REVERSE direction from `xmp_meta.py` / `thumb_cache.py` below, which this pack vendors FROM gallery-loader; each file still has exactly one home, and this one stays here because this pack owns the `/metadata` feature and the parser's attacker-shaped-input suite. Pure-stdlib reader behind `/metadata` — PNG `tEXt`/`zTXt`/`iTXt`, JPEG EXIF (`UserComment`, `ImageDescription`, `Make`/`Model`) + `COM` + XMP APP1, WebP `EXIF`/`XMP ` RIFF chunks, **MP4/MOV `moov/udta/meta/ilst` boxes and Matroska/WebM `SimpleTag` elements** — plus the ComfyUI-graph / A1111-block → `summary` mapper. The two video walks descend structurally and seek past media by declared box/element size, so a `moov` parked after a multi-megabyte `mdat` is reached in a few seeks (ComfyUI's own frontend parser instead reads a bounded 64 MB prefix). Both ilst keyings are handled: the indexed `keys` box core `SaveVideo` writes, **and** the bare `©cmt` iTunes atom kijai's writers use — the latter has no `keys` box at all, which is exactly where the frontend's parser returns early, and it holds a *double-encoded* `{"prompt": …, "workflow": …}` envelope that `_unwrap_comment_envelope` promotes to top-level keys (26% of the videos on the reference install). Verified by diffing every key and value against **PyAV/libav** over all 1387 real video outputs on the GPU box: 1387/1387 agree, zero value mismatches, 1383 parse through to a ComfyUI graph. **No PIL** (conftest stubs PIL with MagicMocks, so a PIL call would return a Mock instead of failing loudly) and no ComfyUI imports. Bounded (`MAX_VALUE_BYTES`/`MAX_TOTAL_BYTES`, bounded inflate, and **two** walk caps — `MAX_TEXT_CHUNKS` on the chunks actually parsed, `MAX_WALK_CHUNKS` on headers merely seeked past, because one shared cap was consumed by a 39 MB PNG's IDAT chunks) and never raises to the caller — every input here is attacker-shaped. **Every cap sets `truncated`**: "the walk gave up" and "the file carries nothing" must not look alike. The budget is charged for a value that is *read* even when a duplicate key drops it, or same-keyed chunks each get a fresh inflate allowance (measured 255 MB of inflate from a 276 KB PNG, on the event loop). Prompt roles are read from the **wiring**, never guessed, and there are now three shapes that satisfy that: the classic `positive`/`negative` conditioning links; a node naming BOTH roles as widgets (`WanVideoTextEncode`'s `positive_prompt`/`negative_prompt`, reached by a `text_embeds` link); and an **unguided single conditioning** (`BasicGuider`, which has no negative because CFG does not apply — so its lone link is unambiguously the positive; this is the MiniMax H3 and core Flux/SD3 path). The link path always wins; the other two are fallbacks, in that order. `MODEL_KEYS` ends with the loose `model` for `WanVideoModelLoader` — safe only because `_scalar` rejects a `[node_id, slot]` list, which is what stops every sampler's MODEL *link* being reported as a model name. Measured over 8632 images + 1387 videos: prompt 77.7%→89.0% and model 94.0%→97.8% for images, prompt 6.1%→30.0% and model 7.9%→62.7% for videos, **zero fields lost or changed**. Still uncovered: `WanVideoSamplerv2` (355 files) moves seed/steps/cfg onto satellite nodes, so `_is_sampler` does not recognise it at all — loosening that predicate risks false positives and is deliberately not done here. Multi-pass graphs: the summarised sampler is the **terminal** one in the latent chain (a sampler another sampler consumes cannot have made these pixels), richness only breaks ties, and a genuine tie omits the sampler fields rather than reporting the wrong pass's seed. Tests: `tests/test_metadata.py` (containers synthesized in-process). |

| `tests/e2e/` | **Browser suite** — Playwright driving real Chromium at a 390×844 phone viewport (`bun run test:e2e`, `just test-e2e`). It exists because the jsdom suite **cannot fail** for the scroll-restore class of bug: jsdom performs no layout, so an empty scroller accepts `scrollTop = 500` and reads back 500 — and keeps reading it back after the node is detached. A real engine silently **clamps** the assignment to `scrollHeight - clientHeight` at the instant of the write, and answers **0** from a detached element (which is the state the kit's teardown leaves the dialog in before `onClose` runs). Both are invisible to Vitest, and both were live defects. `server.mjs` is a stdlib-only stub ComfyUI serving the **built** `web/dist/index.js` at its real extension URL plus `/image_browser/{base,list,thumb}` — real PNG bytes, because a 404 thumb changes the layout under test; listing size is derived from the folder name (`bulk-400` holds 400 files) so the server stays stateless. `fixture.html` opens the modal through the bundle's exported `openShell()`; `harness.js` holds the drivers, `probe.js` the `scrollTop`-setter spy that separates "clamped at assignment" from "moved afterwards". `scroll-restore.spec.js` is the pass/fail suite (REGRESSION = fails against the pre-fix bundle; LOCK = must not break), `scroll-attribution.spec.js` keeps the per-mechanism measurements (clamping, scroll anchoring, restore-vs-observer ordering) as standing assertions so a future change that revives one fails with the number explaining why, `harness.spec.js` self-checks that the harness measures the bundle and not itself. The two gesture tests throttle the renderer (`Emulation.setCPUThrottlingRate`) around the descend: the restore window is only `RESTORE_FRAMES` (~200 ms) while `mouse.wheel`/`keyboard.press` are out-of-process CDP round-trips, so on a loaded machine the gesture arrived *after* the chain had finished and the test passed having proved nothing. Widening the window is the deterministic fix — do not replace it with a sleep or with retries, which hide the race instead of removing it. **Chromium-only**: no WebKit exists here, so iOS **momentum scrolling is NOT covered** by any test — the re-assert loop hardening against it is deliberate and unverified, and a test claiming to cover it would be covering nothing. |
| `justfile` | `build`, `lint`, `format`, `test`, `test-e2e`, `check` recipes — the local CI gate (`check` runs the browser suite too). |

## Hard rules

- **Pack directory name is part of the URL.** `web/dist/index.js` is served at
  `/extensions/comfyui-image-browser/index.js`. Renaming the pack dir breaks every fetch. If
  unavoidable, sync `EXT_NAME` in the source.
- **TypeScript source, bun build.** Author in `src/` (entry `src/index.ts`),
  build to `web/dist/` via `bun build ./src/index.ts --target browser --format
  esm --outdir web/dist --external '/scripts/*'`. `tsc --noEmit` is the type
  gate; `bun build` is the emit — they are decoupled. The `/scripts/app.js`
  import is left **unbundled** (resolved at runtime against ComfyUI's served
  module). See ADR-0001.
- **No new Python dependencies. Backend uses ComfyUI-bundled libs only (aiohttp, PIL, folder_paths, server) + the stdlib (os, shutil, hashlib). A feature needing another lib → a separate companion pack.**
- **Security perimeter — reads gate on extensions, writes are sandboxed.** The arbitrary-path read endpoints (`/thumb`, `/file`, `/metadata`) accept an absolute `path` and MUST gate on a whitelist (`IMG_EXTS` / `STREAMABLE_EXTS` / `METADATA_EXTS` respectively) before touching disk — never read an arbitrary path without one. `METADATA_EXTS` is the narrowest of the three by construction: it admits a video only where `image_meta.FORMAT_EXTS` has a reader, so widening the *listing* to a new container does not silently widen the *parser* perimeter. `/metadata` asserts the whitelist **before** `os.path.isfile`; `/file` still stats first and checks the extension second (a pre-existing wart) — new read endpoints follow `/metadata`'s order. The write endpoints (`/delete`, `/rename`, `/move`) go through `_resolve_sandboxed_file`, which **rejects `type=path`** (writes only in input/output/temp), re-asserts a bare traversal-free filename, the media-extension whitelist, and containment via `commonpath`. **Do not** add an arbitrary-path write path, and **do not** widen a write to `type=path` — arbitrary-path mutation is out of scope by design (ADR-0002). When adding a new file type, widen `IMG_EXTS`/`VIDEO_EXTS` explicitly and add a `tests/test_helpers.py` case.
- **The frontend write UI must mirror the backend's write gate.** `renderGrid` only emits the rename/move/delete buttons for `SANDBOXED_TYPES` (the `canWrite` flag); the `browse…`/path tab shows open-only. If the backend gate changes, change this predicate in lockstep (see `comfyui-pack-live-smoke.md` — a partial frontend mirror ships a dead/available-when-it-shouldn't-be control that passes green tests). The ⓘ metadata and ⤓ load-workflow buttons are the deliberate **exceptions**: `/metadata` is a read that accepts `type=path`, so both render on the browse…/path tab too, gated on the card's extension being in `META_EXTS` instead of on `canWrite`. Don't "fix" them into the mirror. `META_EXTS` is itself a mirror of the backend's `METADATA_EXTS` and is asserted against it by `tests/test_metadata.py::test_frontend_mirror_matches_the_backend_gate`, which reads the literal back out of `src/api.ts` — a hand-copy is exactly how a control ends up present here and rejected there.
- **The lazy-thumb `IntersectionObserver` root must be the scrolling ancestor (`.cmp-body` / `scrollHost`), never `.ib-grid`.** `.ib-grid` has no overflow clip, so with the grid as `root` the root rectangle is the grid's *whole bounding box* and **every** card reports as intersecting on the first callback — the "lazy" load fires for the entire listing at once. Measured: 400/400 off-screen cards intersect with the grid as root vs 20/400 with the scroller. That is survivable in folder view (tens of files) and fatal in flat view (thousands of `/thumb` requests plus a `<video>` element per clip → OOM'd tab). This pattern was inherited from `comfyui-gallery-loader`, where `.gl-grid` **is** the scroller and `root: grid` is correct; it stopped being correct the moment the grid moved inside a modal-shell body. There is a regression test asserting the observer's root.
- **A scroll offset is restored through `restoreScroll()` and read through `currentScrollTop()` — never a bare `scrollHost.scrollTop`.** Four things break the obvious one-liner, all measured in Chromium at a phone viewport. (1) **The close path reads a detached element.** The kit's shell removes the dialog and *then* calls `onClose`, so `rememberScroll()` there reads a node that is out of the document, which every real engine answers with **0** (measured: parked at 31185, stored 0). `liveScrollTop` is the mirror the close path reads instead; any new scroll mutator that bypasses `setScrollTop` must refresh it itself, because the `scroll` event lands at the frame's rendering step — *after* that frame's input events (this is why `applyFocus`'s `scrollIntoView` writes the mirror by hand). (2) **`scrollTop = n` clamps at the instant of assignment**, so one write is only as good as the layout in force; `restoreScroll` re-asserts for a **bounded** `RESTORE_FRAMES` and cancels on close — nothing scheduled may outlive the modal, same rule as `thumbObserver`. (3) **Restore before `installLazyThumbs`**, so the observer's first pass is computed against the final viewport; observing first queues the top-of-list band, which in flat view is thousands of wrong `/thumb` requests. (4) **Hand a known destination *into* `renderGrid({ scrollTo })`** rather than assigning after it — a later write races the re-assert loop, and `renderGrid`'s own capture belongs to the folder you just left. Any user gesture that scrolls (pointer/wheel/touch, or a native scroll key outside an input) ends the restore immediately: a wrong offset beats a scroller that fights a finger. `tests/e2e/` is the only suite that can see any of this.
- ****Modal primitives come from `@laurigates/comfy-modal-kit`** — import them, do NOT copy `modal-shell.js`/`modal-fuzzy.js` into the pack. `bun build` inlines the imported code into `web/dist`.**
- **Additive only.** Never clobber an existing tooltip/control; fall back to
  the native widget when there's no match. Never fabricate data.
- **Launcher API is version-sensitive.** The modal opens from `registerExtension`'s `actionBarButtons` / `commands` / `menuCommands`. If a future frontend renames or drops one, keep at least one launcher (button OR command) wired so the modal stays reachable.
- **Never hand-edit `CHANGELOG.md` or the `version` field** — release-please
  owns them (conventional commits drive the bump).

## Dev workflow

```sh
uv sync --group dev          # ruff, pytest, pre-commit
bun install                  # TypeScript, Biome, Vitest, knip, @laurigates/comfy-modal-kit (inlined at build)
pre-commit install
just check                   # typecheck + build + lint + test + test-e2e — the local CI gate
```

Two test environments, and the split is load-bearing:

```sh
bun run test                 # Vitest/jsdom (tests/js/) — no layout engine
just test-e2e                # builds, then Playwright/Chromium (tests/e2e/)
bun run test:e2e             # the browser suite alone (serves the CURRENT web/dist — build first)
bun run test:e2e:headed      # same, with a visible browser
```

`tests/js/` cannot fail for anything layout-dependent: jsdom accepts
`scrollTop = 500` on a zero-height scroller and reads it back verbatim, detached
or not. Scroll, clamping and lazy-load behaviour therefore only get asserted in
`tests/e2e/` — Chromium-only, so iOS momentum scrolling stays uncovered.

Iterating on the frontend needs a **`bun run build`** (the served file is
`web/dist/index.js`, not the source) plus a browser hard-refresh — no ComfyUI
restart. Changes to `image_browser.py` (backend) DO require a ComfyUI restart.

## Verify the frontend API against the sourcemap

The ComfyUI frontend (`comfyui-frontend-package`) ships **minified** — property
and method names are renamed in the bundle, so reading the running app's objects
by guessed names (or trusting old tutorials) is unreliable. The TypeScript types
from `@comfyorg/comfyui-frontend-types` cover `ComfyApp` but **not** the internal
`LGraphNode` / `LGraphCanvas` / widget interfaces (un-exported). Model the small
surface you touch with local structural interfaces, and verify the real shape
against the bundled sourcemap before coding against a LiteGraph / canvas API.

LiteGraph is bundled in the **`api-*.js.map`** chunk under
`.venv/lib/python*/site-packages/comfyui_frontend_package/static/assets/`. The
`.js.map` embeds the original TypeScript in `sourcesContent` — grep that, not the
minified `.js`:

```sh
cd .venv/lib/python*/site-packages/comfyui_frontend_package/static/assets
grep -l 'LGraphGroup' *.js.map        # find the chunk
```

Facts worth confirming this way (recheck on a `comfyui-frontend-package` bump):
`LiteGraph.NODE_TITLE_HEIGHT` (30); `canvas.selectedItems` is a
`Set<Positionable>` holding nodes + groups + reroutes; `canvas.selected_nodes` is
a node-only dictionary; canvas zoom is **wheel-driven**
(`processMouseWheel -> ds.changeScale`).

Two gotchas that follow: discriminate selected items by **shape, not
`instanceof`** (the class is renamed under minification); and to suppress native
zoom during a gesture, intercept `wheel` (capture, `passive:false`,
`preventDefault`), not just pointer events. Record what you confirm in a
"Verified frontend API" table above so the next change doesn't re-derive it.
