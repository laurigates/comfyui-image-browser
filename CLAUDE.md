# CLAUDE.md

ComfyUI custom-node pack with a thin Python backend (a node + HTTP endpoints in `image_browser.py`) and a TypeScript frontend extension built to `web/dist/` via bun. See ADR-0001.

## The pattern ("the vein")

A mobile-first ComfyUI usability pack in the *standalone-modal* vein: instead of intercepting a per-node widget, a frontend extension opens a STANDALONE modal from the app chrome — a command (palette/hotkey-bindable), a menu entry, and a row in the family's shared **Touch Tools** action-bar button. This pack no longer ships a topbar button of its own: the family owns exactly one, and whichever inlined kit copy calls `installHubButton()` first claims it for the page. There are **no target widgets to hook**, so there is no `TARGET_WIDGETS` / `onPointerDown` wrapping. The modal is **touch-first** (16px inputs to avoid iOS zoom, big tap targets, momentum scroll); its primitives come from `@laurigates/comfy-modal-kit` (`openModalShell` / `fuzzyScore` / `notify` / `makeHubEntry` + `installHubButton` + `registerHubEntry` / `ensureStyleOnce`, plus the in-dialog `openShellOverlay` / `confirmInShell` / `promptInShell` used for delete-confirm, rename, the move picker, and the metadata card — kept in-dialog, not a second `openModalShell`, so single-modal discipline doesn't close the browser), imported and inlined by `bun build` — not copied into the pack. `openShell()` is exported so the jsdom mount test can prove the modal body renders.

Concretely, this pack is a **full-canvas image browser + file manager**: the modal
fills the whole viewport (`width: 100vw; height: 100vh` on `.ib-dialog`), standing
in for the canvas while open. It reuses the card-grid file-explorer pattern proven
in `comfyui-gallery-loader`'s `image-picker` (breadcrumbs, thumbnail grid,
lazy-load, sort, fuzzy search), but as a standalone view that **manages** files
(delete / rename / move) rather than committing a value to a node widget. There is
**no custom node** — `NODE_CLASS_MAPPINGS` is intentionally empty; all value lives
in the HTTP endpoints + the served bundle.

## Endpoint surface (`/image_browser/`)

| Endpoint | Method | Purpose |
|---|---|---|
| `/base` | GET | ComfyUI well-known dirs (base/input/output/temp/user). Frontend hard-codes no paths. |
| `/list` | GET | Directory listing (`type=input\|output\|temp\|path`, `subfolder`/`path`, `extensions`, `kind`). **`kind=images\|videos`** narrows to one media family (the toolbar's segmented filter) by intersecting `KIND_FILTERS` into the extension set — it *composes* with `extensions=` rather than overriding it, applies **above** the recursive/non-recursive split and above the mtime sort + cap, and unlike `recursive` is **not** gated to the sandboxed roots (extension filtering costs nothing extra on `type=path`). An unrecognised `kind` narrows nothing rather than 400ing, since the request is still answerable. Placing it above the cap is the whole point: `kind=videos` returns the newest N *videos*, where a client-side filter would return the videos among the newest N files. Returns `{dirs, files}`; each file carries `mtime/size/width/height/ext/rating/`**`tags`**. `tags` is the file's `dc:subject` keywords, read out of the SAME XMP packet as the rating through one `xmp_meta.read_meta_cached` call — Safe View's third haystack. With `safe_hide=1` they are matched too, but **not** where the name/path tier is matched: a tag verdict needs the XMP read, which is the expensive probe the cap exists to bound, so `_probe_newest` probes newest-first and **tops up** — a row dropped for its tags is replaced by probing one more, bounded by `PROBE_BUDGET_FACTOR`. Filtering after the slice instead would answer a tagged folder with an empty grid; probing everything would open the whole tree. With **`recursive=1`** (sandboxed roots only — ignored for `type=path`) it returns the **flat view**: every descendant file under `subfolder`, `dirs:[]`, each file tagged with a forward-slashed `subpath` relative to `subfolder` (`""` at the top level). Stops at `FLAT_LIST_CAP` files and sets `truncated:true`. The **non-recursive** path is capped too (`DIR_LIST_CAP`), through the same `_probe_newest` — both cap by mtime after sorting, never during the walk, so a truncated listing holds the newest N rather than whatever directory order reached first. Symlinked dirs are not followed. **`safe_prompt=1`** (with a non-empty `safe_kw`) turns on Safe View's opt-in prompt tier: each participating file gains a `prompt_match` of `true` / `false` / `"unscanned"`, and the response gains `safe_unscanned`. A file whose container has no metadata reader gets **no key at all** — "nothing to scan" and "not scanned yet" are different states, and the frontend's `PromptVerdict` carries the same four. Verdicts come from `safeview_store.py`'s cache and are matched with the SAME `is_safe_match` the name/path haystacks use; the prompt TEXT never leaves the server. With `safe_hide=1` the two compose and the verdict decides membership above the cap, `"unscanned"` included (mirroring the kit's `isSensitive`). |
| `/thumb` | GET | Cached WebP thumbnail for **all** image listings — `?type=&subfolder=&name=` (sandboxed) or `?path=` (absolute). Served through the shared on-disk cache (`thumb_cache.py`) with ETag + long `max-age`; URLs embed `?v=<mtime>-<size>`. Never use core `/api/view` for thumbnails (it re-encodes every request, no cache headers). |
| `/metadata` | GET | Embedded generation metadata for one file — same dual addressing as `/thumb` (`?type=&subfolder=&name=` or `?path=`), same resolver (`_resolve_thumb_target`). Gated on **`METADATA_EXTS` before `os.path.isfile`** — every image, plus the video containers `image_meta` can read (MP4/MOV/M4V, WebM/MKV); **derived** from `image_meta.FORMAT_EXTS`, so `.avi`/`.mpg` (in `VIDEO_EXTS`, no reader) are excluded. Non-whitelisted extension → **400**, missing file → **404**. Returns `{format, source: comfyui\|a1111\|none, summary, raw, truncated}`: `format` is extension-derived (`""` for an image with no parser, e.g. `.gif` → 200 with empty metadata, never a 500); `summary` keys the parser could not read are **omitted, never guessed**; `raw` is every embedded text key verbatim, capped. Read-only, no cache headers (one-shot tap-to-open read). |
| `/file` | GET | Stream an absolute-path file (image/video), extension-gated. |
| `/delete` | POST | `{type, subfolder, name}` — delete a file. |
| `/rename` | POST | `{type, subfolder, name, new_name}` — rename in place. |
| `/move` | POST | `{type, subfolder, name, dest_type, dest_subfolder}` — move a **file** between roots/subfolders. |
| `/move_dir` | POST | `{type, subfolder, name, dest_type, dest_subfolder}` — move a **folder** (whole subtree) between roots/subfolders. Sandboxed types only; symlinked source rejected; refuses moving a folder into itself or a descendant (**400**). A same-named folder at the destination **merges** (`ok:true, merged:true`): contents move in, matching subfolders merge recursively, and any entry that would overwrite an existing file is left in the source and reported in `errors[]` (nothing is clobbered). A same-named *file* at the destination is still a hard **409**. |
| `/delete_many` | POST | `{items:[{type,subfolder,name},…]}` — batch delete; per-item errors in `errors[]`, partial success is still `ok:true`. |
| `/move_many` | POST | `{items:[…], dest_type, dest_subfolder}` — batch move into one destination; same per-item error contract. |
| `/rmdir` | POST | `{type, subfolder, name, recursive}` — delete a folder. Empty deletes outright; non-empty without `recursive:true` answers **409 with nested `{files, dirs}` counts** so the UI confirms with the real number before re-posting `recursive:true`. Sandboxed types only; symlinked dirs rejected. |
| `/mkdir` | POST | `{type, subfolder, name}` — create a folder under the current subfolder. Sandboxed types only; bare traversal-free name. A missing parent answers 404; an existing target (file or folder) answers **409** so the UI surfaces a name collision. |
| `/rating` | POST | `{type, subfolder, name, rating}` — persist a 0..5 star rating into the file's XMP (or sidecar). Sandboxed types only, like all writes. |
| `/tag` | POST | `{type, subfolder, name, tag, present}` — add (`present:true`) or remove ONE `dc:subject` keyword. Sandboxed types only through `_resolve_sandboxed_file`, exactly like `/rating` — a keyword write is a write, so `type=path` is rejected (ADR-0002). `tag` is normalized by `xmp_meta.normalize_tag`, the same function the writer uses, so a value that could not survive the round trip is refused rather than mangled; a non-boolean `present` is a **400** rather than a coercion (a truthy `"false"` would add the keyword a tap meant to remove). `xmp_meta.write_tags` is a **delta**, so the file's other keywords and its rating both survive. The response carries `read_tags(target, head_only=False)` — **what was actually stored**, never an echo of the request: the two differ whenever the file already carried the keyword under another casing or the write landed in a sidecar, and painting the request would show a mark the file does not have. |
| `/pins` | GET | The shared pin list, each entry resolved: `{ok, max, pins}`. A pin is `{kind: dir\|file, type: input\|output\|temp, subfolder, name?}` (`name` iff `kind=file`); `type=path` is **rejected** by the store — pins are a sandboxed-roots concept, the same perimeter as every write. Every entry carries **`exists`**, and an unresolvable one is returned with `exists:false` rather than dropped: "the file moved" and "you never pinned it" are different facts (same reasoning as `/ratings` answering `null` instead of `0`). A resolvable **file** pin additionally carries the same per-file keys `/list` emits (`mtime/size/width/height/ext/rating`), which is what lets the pinned view render through the ordinary `renderGrid` with no special-casing. |
| `/pins` | POST | Apply ONE **delta**: `{op: "add"\|"remove"\|"prune", item?}` (`item` omitted for `prune`). Deliberately **not** a whole-list PUT — two browsers with the modal open would each send their own full list and the second write would silently discard the first's pin; a delta read-modify-written inside one aiohttp handler cannot interleave. Answers with the **same shape as the GET** (the whole freshly-resolved list) so the caller needs no follow-up GET. Adding an already-present pin is a successful no-op, which is what makes the frontend's localStorage migration replayable. Refusals are `{ok:false, error}` + 400 (500 on a write failure); the cap reads `pin limit reached (max 200)` and the UI must surface it **verbatim** rather than let an add vanish. |
| `/safeview_warm` | POST | `{items:[{type,subfolder,name}, …]}` — parse and cache the prompt metadata of the files a render just produced, answering `{ok, scanned}`. The prompt tier's **fast** cache warmer, driven by the frontend's `executed` websocket listener; the backend's lazy background sweep is the **backlog** warmer and neither subsumes the other (the sweep cannot see a render that happens after it finishes; the listener cannot see a library that predates the tab). Sandboxed roots only — `_resolve_sandboxed_file`, the same perimeter as every write and the batch rating read. A file with no metadata reader is **skipped, not refused**: the frontend posts every output of one execution and a mixed batch must not fail on one `.avi`. Capped at `MAX_WARM_BATCH` (64); the parse runs in an executor. |
| `/ratings` | POST | `{items:[{type,subfolder,name}, …]}` — batch **READ** of ratings for the sidebar injector. Answers `{ok, ratings}` **index-aligned with `items`**. A per-item `null` (never `0`) means *could not read* — rejected address, missing file — because "unrated" and "unknown" must not look alike to a caller that paints stars. Capped at `MAX_RATING_BATCH` (200) so a client cannot ask the event loop to stat a whole output tree. Reads go through `xmp_meta.read_rating_cached`. Gated by `_resolve_sandboxed_file`, the same resolver the rating *write* uses — strictly laxer would do for a read, but ratings are a sandboxed-roots concept here and one perimeter is easier to keep correct than two. |

## File layout

| Path | Purpose |
|------|---------|
| `src/index.ts` | The extension: the two settings, the `makeHubEntry` command/menu/chooser-row declaration, the `installHubButton()` claim on the family's one action-bar button, and the `setup()` that registers the chooser row (registering at module scope would list this pack even when disabled). Exports `openShell()` → `openImageBrowser()`. |
| `src/browser.ts` | The full-canvas explorer — grid, tabs, breadcrumbs, sort/search, per-card delete/rename/move, the move-destination picker, and all CSS. The flat-view preference goes through the kit's `createViewStore(VIEW_NAMESPACE)`; **`VIEW_NAMESPACE` is `"comfyui-image-browser"` and is frozen** — it is the localStorage prefix this pack has written since flat view shipped, so any other value reads a key nobody wrote and orphans every user's stored preference with no visible tell. It must not be shared with `comfyui-gallery-loader` either: two surfaces over different roots. Pinned in `tests/js/kit-listing.test.js`. |
| `src/label.ts` | Pure, DOM-free card-label shaping: `stripCounter` and `splitTail`, consumed by `renderGrid`'s `nameSpans`. `.ib-name` renders as a head span the browser ellipsizes and a tail span that never elides, because output names share a long `hhmmss_sampler_scheduler_seed_` prefix and differ at the END — an ordinary end-ellipsis eats the only identifying part. Deliberately NOT a character budget computed from the grid's `minmax()`: `auto-fill` almost never hands out the minimum track, so such a budget over-truncates at every width above the floor, and the pack already carries one CSS-mirrored-in-TS hazard (`CARD_MIN_WIDTH`). Two facts pinned by real sampled filenames rather than invented ones: the save counter has **two** on-disk spellings (`_00001_` from core, `_00074` from kijai's writer), and it is only stripped from names carrying the convention's `hhmmss_` prefix — a legacy `flux_kontext_00078_.png` has the counter as its ONLY discriminator, so stripping unconditionally would give two distinct files one label. The **extension is kept**: a thumbnail says image-or-video, never which container, and `.webm` vs `.mp4` decides whether a clip is decodable (see `bundled-lib-not-system-lib.md`). |
| `src/api.ts` | Typed wrappers over the `/image_browser/*` endpoints + thumbnail/preview URL builders. No DOM. The **listing vocabulary is the kit's** since 0.14.0 — `IMG_EXTS` / `VIDEO_EXTS` / `joinAbs` / `META_FIELDS` + `metaRows` + `metaClipboardText` are imported from `@laurigates/comfy-modal-kit` and are deliberately **not** re-exported here (a second name for the same thing is where the next drift hides). What stays local is what is genuinely this pack's: `META_VIDEO_EXTS` (narrower than the kit's video set — only containers with a reader), the derived `META_EXTS`, `BrowseType`, and `SANDBOXED_TYPES`, which is the **kit's array narrowed by a cast** to `readonly BrowseType[]` (the kit types it `readonly string[]` because each pack's location union differs). `fetchBasePaths` / `fetchMetadata` also stay: they pass `{ cache: "no-cache" }` where `comfyui-gallery-loader` does not, and which side is right is undecided — do not settle it by extraction. |
| `src/sidebar-stars.ts` | **One of two modules that touch stock ComfyUI UI** (see `src/lightbox-actions.ts` for the other). Injects a star row into the cards of ComfyUI's own *Media Assets* sidebar, behind the `ImageBrowser.SidebarStars` setting (default on; the settings store fires `onChange` once at registration, so the setting IS the lifecycle — there is no separate startup call to keep in sync). It is **not** a `comfyui-touch-shim` shim: shims paper over upstream *bugs* and carry a filed issue plus a death date, whereas this adds a capability the stock UI never had, and lives here because this pack already owns `/rating` and the XMP code. Three constraints keep it survivable, and all three are load-bearing: (1) **the grid is virtualized** — card DOM nodes are RECYCLED for different files as you scroll, so no state may be bound to a node; every pass re-reads the address off the card's own `<img>` and repaints from an address-keyed cache. The teardown-on-address-change guard exists for a **transient** window only (the steady state self-corrects via `applyStars` once the batch read lands) — its regression test therefore stalls the read and asserts *mid-flight*, because a settled-state assertion passes with the guard disabled (measured). (2) **Identity is the preview URL**, `/api/view?filename=&subfolder=&type=`, because at 1.47.x the card root has no `data-asset-id` (`main` has since added one) and the URL is the only identity present in both — conveniently already the address the rating endpoints take. (3) **Fail soft**: a rotted selector renders nothing; each pass is wrapped, mutations are coalesced (`SETTLE_MS`), and the click listener is delegated + capture-phase (the stock card stops propagation on its own root). The `CARD_SELECTOR` scoping is a cost/clarity choice, **not** the correctness guard — `cardRootOf()` is what actually keeps stars off canvas node previews and the lightbox (verified: the scoping test still passes with the selector widened to `"img"`). That exclusion still holds — the lightbox's bar comes from `lightbox-actions.ts`, which paints inside the lightbox dialog only; the two injectors never render into each other's territory. |
| `src/rating-cache.ts` | Address parsing (`parseAssetAddress`) + the **shared** address→rating cache both injectors read and write, extracted when the lightbox needed them too. Shared on purpose: rating in the lightbox must show on the card underneath once it closes. Keyed by file address, never by DOM node — see the recycling note above. |
| `src/lightbox-actions.ts` | **The second stock-UI injector.** Adds a star row + a delete button to `MediaLightbox.vue`, the full-screen viewer that *Inspect asset* opens (and that the Queue sidebar reuses), behind `ImageBrowser.LightboxActions` (default on, same onChange-is-the-lifecycle pattern). Verified identical in the shipped 1.47.10 bundle and 1.50.0 source: a Teleport-to-body `[role=dialog][aria-modal=true][data-mask]` whose own keydown handler maps ←/→ to navigation and Esc to close. **`data-mask` is the discriminator** — it is what separates the lightbox from every other dialog teleported to body. Four load-bearing constraints: (1) **one dialog element outlives many items** — navigating swaps the media `src` in place, so like a recycled card no state may be bound to the bar; a changed address REBUILDS it and blanks the stars to 0 rather than leaving the previous file's rating on the new image. That guard's test stalls the read and asserts mid-flight for the same reason the sidebar's does (measured: both fail with the guard removed). (2) **Navigation goes through the component's own key contract** (dispatch ArrowRight / Escape), never by clicking its buttons — those carry i18n'd aria-labels and utility-class icons, both of which move between versions. `hasMultipleItems()` reads the next-control's icon class, the most brittle thing here, and is deliberately fail-*single*: a rotted match closes the lightbox after a delete instead of advancing onto the file just deleted. (3) **The delete confirm swallows keydown in the capture phase** while up, so ←/→ cannot move to a different file between the question and the answer — otherwise the answer deletes the wrong one. It is a local overlay rather than the kit's `confirmInShell`, which needs a `ModalShellController` (`_onKey`) that does not exist here. (4) **The item list is the sidebar's prop and cannot be refreshed from here**, so a deleted file stays navigable; the module remembers it for the session and paints a plain "Deleted" notice instead of rateable stars. Unlike the sidebar's batch cache this one re-reads its single address on every navigation, so it is never stale. **Never widen the `/api/view` gate to `/api/viewvideo`** — that is the tempting one-liner for "videos get no bar" and it would delete the WRONG FILE. `AssetsSidebarTab.vue` builds each `ResultItemImpl` with `subfolder: ''` hard-coded and overrides only the `url` getter (to the asset's real `preview_url`), so `/api/view` carries the true subfolder while `ResultVideo`'s `vhsAdvancedPreviewUrl` is rebuilt from the discarded one. Measured live on 1.47.10: a `.webm` in `output/nsfw/2026-08-04/` → `/api/viewvideo?…&subfolder=` → **HTTP 204 empty** (the stock viewer shows a blank player — upstream bug), while the card's `/api/view` for the same file → 206. The `/api/view` restriction is the discriminator between "the asset's real address" and "an address rebuilt from state the frontend threw away"; there is a regression test asserting the refusal. |
| `src/comfyui-shims.d.ts` | Types the `/scripts/app.js` runtime import (via the `paths` mapping in `tsconfig.json`). |
| `__init__.py` | Loader stub. Imports (empty) node mappings from the backend module; exports `WEB_DIRECTORY = "./web/dist"`. |
| `image_browser.py` | HTTP endpoints only (no node). Bundled libs + stdlib only; reads gate on an extension whitelist, writes are sandboxed to input/output/temp. |
| `image_meta.py` | **Canonical home — edit it HERE.** `comfyui-gallery-loader` now vendors it (its `just sync-image-meta` + CI drift check pull from this repo's `main`), so a change here must be synced downstream. Note this is the REVERSE direction from `xmp_meta.py` / `thumb_cache.py` below, which this pack vendors FROM gallery-loader; each file still has exactly one home, and this one stays here because this pack owns the `/metadata` feature and the parser's attacker-shaped-input suite. Pure-stdlib reader behind `/metadata` — PNG `tEXt`/`zTXt`/`iTXt`, JPEG EXIF (`UserComment`, `ImageDescription`, `Make`/`Model`) + `COM` + XMP APP1, WebP `EXIF`/`XMP ` RIFF chunks, **MP4/MOV `moov/udta/meta/ilst` boxes and Matroska/WebM `SimpleTag` elements** — plus the ComfyUI-graph / A1111-block → `summary` mapper. The two video walks descend structurally and seek past media by declared box/element size, so a `moov` parked after a multi-megabyte `mdat` is reached in a few seeks (ComfyUI's own frontend parser instead reads a bounded 64 MB prefix). Both ilst keyings are handled: the indexed `keys` box core `SaveVideo` writes, **and** the bare `©cmt` iTunes atom kijai's writers use — the latter has no `keys` box at all, which is exactly where the frontend's parser returns early, and it holds a *double-encoded* `{"prompt": …, "workflow": …}` envelope that `_unwrap_comment_envelope` promotes to top-level keys (26% of the videos on the reference install). Verified by diffing every key and value against **PyAV/libav** over all 1387 real video outputs on the GPU box: 1387/1387 agree, zero value mismatches, 1383 parse through to a ComfyUI graph. **No PIL** (conftest stubs PIL with MagicMocks, so a PIL call would return a Mock instead of failing loudly) and no ComfyUI imports. Bounded (`MAX_VALUE_BYTES`/`MAX_TOTAL_BYTES`, bounded inflate, and **two** walk caps — `MAX_TEXT_CHUNKS` on the chunks actually parsed, `MAX_WALK_CHUNKS` on headers merely seeked past, because one shared cap was consumed by a 39 MB PNG's IDAT chunks) and never raises to the caller — every input here is attacker-shaped. **Every cap sets `truncated`**: "the walk gave up" and "the file carries nothing" must not look alike. The budget is charged for a value that is *read* even when a duplicate key drops it, or same-keyed chunks each get a fresh inflate allowance (measured 255 MB of inflate from a 276 KB PNG, on the event loop). Prompt roles are read from the **wiring**, never guessed, and there are now three shapes that satisfy that: the classic `positive`/`negative` conditioning links; a node naming BOTH roles as widgets (`WanVideoTextEncode`'s `positive_prompt`/`negative_prompt`, reached by a `text_embeds` link); and an **unguided single conditioning** (`BasicGuider`, which has no negative because CFG does not apply — so its lone link is unambiguously the positive; this is the MiniMax H3 and core Flux/SD3 path). The link path always wins; the other two are fallbacks, in that order. `MODEL_KEYS` ends with the loose `model` for `WanVideoModelLoader` — safe only because `_scalar` rejects a `[node_id, slot]` list, which is what stops every sampler's MODEL *link* being reported as a model name. Measured over 8632 images + 1387 videos: prompt 77.7%→89.0% and model 94.0%→97.8% for images, prompt 6.1%→30.0% and model 7.9%→62.7% for videos, **zero fields lost or changed**. Still uncovered: `WanVideoSamplerv2` (355 files) moves seed/steps/cfg onto satellite nodes, so `_is_sampler` does not recognise it at all — loosening that predicate risks false positives and is deliberately not done here. Multi-pass graphs: the summarised sampler is the **terminal** one in the latent chain (a sampler another sampler consumes cannot have made these pixels), richness only breaks ties, and a genuine tie omits the sampler fields rather than reporting the wrong pass's seed. Tests: `tests/test_metadata.py` (containers synthesized in-process). |
| `safeview_store.py` | **Canonical home — edit it HERE**, like `image_meta.py` (which it calls) and for the same reason; `comfyui-gallery-loader` will vendor it downstream. Note this is the REVERSE direction from `xmp_meta.py` / `thumb_cache.py` / `pins_store.py` below. Pure-stdlib (`sqlite3`) cache behind Safe View's opt-in prompt tier: the extracted prompt+model **text** per file, keyed by `sha1(path:mtime_ns:size)` — byte-identical in shape to `thumb_cache.cache_key`, so there is one invalidation model, not two — in `<user_dir>/comfy-safeview.sqlite`, shared with gallery-loader the same way the thumbnail cache is. It caches **TEXT, not a verdict**: a cached verdict would key on (file, keywords) and every keyword edit would invalidate the whole library, on the one tier where re-scanning is expensive. A file that yields nothing is still cached (as `""`) — "scanned, carries no prompt" and "not scanned yet" are different facts, and conflating them re-scans every screenshot forever. Also holds the background **sweep**: an executor-bounded walk + parse, batched at `SWEEP_BATCH` with a yield between batches so a shutdown cancels within one batch. Every cache failure degrades to "unscanned" rather than raising — a listing must answer on a read-only user dir. |
| `src/scan-warm.ts` | The prompt tier's other warmer: an `executed` websocket listener (`app.api`, an `EventTarget`) that POSTs the render's outputs to `/safeview_warm`. Installed unconditionally in `setup()` and gated at EVENT time on `MatchPrompt`, so switching the tier on mid-session needs no reload and leaving it off costs one idle listener. It reads **`images` AND `video`** — every field of `zResultItem` is optional and `zOutputs` carries three arrays, so an item with no `filename` is skipped rather than turned into a bogus address, and reading only `images` would leave every freshly generated clip permanently unscanned and therefore permanently blurred. `audio` is deliberately absent: no audio container has a reader. |
| `src/safe-tag.ts` | The `🙈` mark-sensitive control's **per-pack half**: whether a file already carries EXACTLY the keyword (`hasSensitiveTag`, case-insensitive but not "would the filter match it" — a file tagged `nsfw art` is blurred by `nsfw` and does not carry it), the `/tag` request body and the button markup. A **PORT** of `comfyui-gallery-loader/src/safe-tag.ts`, not a shared module, and the deliberate difference is that this one has **no `type: "path"` arm** — there is no path-tab card to write from here (ADR-0002), its `TagAddress` carries no `absDir`, and `markSensitiveHTML` emits this pack's own class prefix. Unifying any of those would silently reverse a considered decision. **Which keyword it writes is the KIT's** since 0.14.0 — `sensitiveKeyword` (the user's FIRST configured one, never a hidden constant, `null` ⇒ the control is not rendered at all) was the one function that must not stay duplicated, because the two packs write over the same files and a divergence would mark a file here that the other pack's filter then ignored. ## Hard rules

- **Pack directory name is part of the URL.** `web/dist/index.js` is served at
  `/extensions/comfyui-image-browser/index.js`. Renaming the pack dir breaks every fetch. If
  unavoidable, sync `EXT_NAME` in the source.
- **TypeScript source, bun build.** Author in `src/` (entry `src/index.ts`),
  build to `web/dist/` via `bun build ./src/index.ts --target browser --format
  esm --outdir web/dist --external '/scripts/*'`. `tsc --noEmit` is the type
  gate; `bun build` is the emit — they are decoupled. The `/scripts/app.js`
  import is left **unbundled** (resolved at runtime against ComfyUI's served
  module). See ADR-0001.
- **No new Python dependencies. Backend uses ComfyUI-bundled libs only (aiohttp, PIL, folder_paths, server) + the stdlib (os, shutil, hashlib). A feature needing another lib → a separate companion pack.**
- **Security perimeter — reads gate on extensions, writes are sandboxed.** The arbitrary-path read endpoints (`/thumb`, `/file`, `/metadata`) accept an absolute `path` and MUST gate on a whitelist (`IMG_EXTS` / `STREAMABLE_EXTS` / `METADATA_EXTS` respectively) before touching disk — never read an arbitrary path without one. `METADATA_EXTS` is the narrowest of the three by construction: it admits a video only where `image_meta.FORMAT_EXTS` has a reader, so widening the *listing* to a new container does not silently widen the *parser* perimeter. `/metadata` asserts the whitelist **before** `os.path.isfile`; `/file` still stats first and checks the extension second (a pre-existing wart) — new read endpoints follow `/metadata`'s order. The write endpoints (`/delete`, `/rename`, `/move`) go through `_resolve_sandboxed_file`, which **rejects `type=path`** (writes only in input/output/temp), re-asserts a bare traversal-free filename, the media-extension whitelist, and containment via `commonpath`. **Do not** add an arbitrary-path write path, and **do not** widen a write to `type=path` — arbitrary-path mutation is out of scope by design (ADR-0002). When adding a new file type, widen `IMG_EXTS`/`VIDEO_EXTS` explicitly and add a `tests/test_helpers.py` case.
- **The frontend write UI must mirror the backend's write gate — per CARD, not per location.** `renderGrid` only emits the rename/move/delete/📌 buttons, the stars and the ✓ checkbox for a card whose own root is in `SANDBOXED_TYPES` — the **`canWriteFile(f)`** predicate, which reads `fileType(f)` (`f.pinType ?? state.type`). The `browse…`/path tab shows open-only. The location-level `canWrite` flag still exists and still governs the `..`/folder cards and the toolbar's directory-only controls (`≣`, `📁+`, `📌`), but **must never be used for a per-card control**: in the pinned view `state.type` is `"pinned"`, which is not a sandboxed root, so a location-level gate there would ship a grid of writable files with every write control missing. Same law one level down: `fileSub(f)` and `fileType(f)` are paired at every per-file address (thumbnail, open, metadata, workflow, rating, delete/rename/move, selection key, pin) — pairing `fileSub(f)` with a bare `state.type` addresses the right name under the wrong root, which in the pinned view is a **different file**. `tests/js/` asserts a two-root pinned grid for exactly this; that assertion was verified by reverting `fileType` to `return state.type` and watching it go red. If the backend gate changes, change this predicate in lockstep (see `comfyui-pack-live-smoke.md` — a partial frontend mirror ships a dead/available-when-it-shouldn't-be control that passes green tests). The ⓘ metadata and ⤓ load-workflow buttons are the deliberate **exceptions**: `/metadata` is a read that accepts `type=path`, so both render on the browse…/path tab too, gated on the card's extension being in `META_EXTS` instead of on `canWrite`. Don't "fix" them into the mirror. `META_EXTS` is itself a mirror of the backend's `METADATA_EXTS` and is asserted against it by `tests/test_metadata.py::test_frontend_mirror_matches_the_backend_gate`, which reads the literal back out of `src/api.ts` — a hand-copy is exactly how a control ends up present here and rejected there.
- **The lazy-thumb `IntersectionObserver` root must be the scrolling ancestor (`.cmp-body` / `scrollHost`), never `.ib-grid`.** `.ib-grid` has no overflow clip, so with the grid as `root` the root rectangle is the grid's *whole bounding box* and **every** card reports as intersecting on the first callback — the "lazy" load fires for the entire listing at once. Measured: 400/400 off-screen cards intersect with the grid as root vs 20/400 with the scroller. That is survivable in folder view (tens of files) and fatal in flat view (thousands of `/thumb` requests plus a `<video>` element per clip → OOM'd tab). This pattern was inherited from `comfyui-gallery-loader`, where `.gl-grid` **is** the scroller and `root: grid` is correct; it stopped being correct the moment the grid moved inside a modal-shell body. There is a regression test asserting the observer's root.
- **A scroll offset is restored through the kit's `installScrollRestore()` and read through `scroller.current()` — never a bare `scrollHost.scrollTop`.** The mechanism itself lives in `@laurigates/comfy-modal-kit`'s `scroll-restore.ts` (with `createScrollMemory()` for the per-directory map), because `comfyui-gallery-loader`'s picker needs identical behaviour over the same card grid; a second copy would drift, and this pack's browser tier is the only place either copy could be measured. Four things break the obvious one-liner, all measured in Chromium at a phone viewport. (1) **The close path reads a detached element.** The kit's shell removes the dialog and *then* calls `onClose`, so `rememberScroll()` there reads a node that is out of the document, which every real engine answers with **0** (measured: parked at 31185, stored 0). The restorer's mirror is what the close path reads instead — hence `scroller.dispose()` runs **after** `rememberScroll()` in `onClose`, not before — and any scroll mutator that bypasses `scroller.set()` must call `scroller.sync()` itself, because the `scroll` event lands at the frame's rendering step, *after* that frame's input events (this is why `applyFocus`'s `scrollIntoView` syncs by hand). (2) **`scrollTop = n` clamps at the instant of assignment**, so one write is only as good as the layout in force; the restorer re-asserts for a **bounded** `SCROLL_RESTORE_FRAMES` and `dispose()` cancels on close — nothing scheduled may outlive the modal, same rule as `thumbObserver`. (3) **Restore before `installLazyThumbs`**, so the observer's first pass is computed against the final viewport; observing first queues the top-of-list band, which in flat view is thousands of wrong `/thumb` requests. (4) **Hand a known destination *into* `renderGrid({ scrollTo })`** rather than assigning after it — a later write races the re-assert loop, and `renderGrid`'s own capture belongs to the folder you just left. Any user gesture that scrolls (pointer/wheel/touch, or a native scroll key outside an input — `isTypingTarget` is wired to this pack's `isInInput`, since the search field is autofocused) ends the restore immediately: a wrong offset beats a scroller that fights a finger. `tests/e2e/` is the only suite that can see any of this; the kit's own suite asserts the bookkeeping and says so.
- ****Modal primitives come from `@laurigates/comfy-modal-kit`** — import them, do NOT copy `modal-shell.js`/`modal-fuzzy.js` into the pack. `bun build` inlines the imported code into `web/dist`.**
- **Safe View is DISCRETION, NOT ACCESS CONTROL, and every surface must agree
  on what matches.** The blur is a CSS class and the blurred bytes are still
  fetched; say so wherever it is documented, because a reader who mistakes it
  for protection will trust it with something it cannot protect. Everything
  shared — the settings, the token matcher, the blur/spoiler CSS, the reveal
  button — comes from `@laurigates/comfy-modal-kit`'s `safe-view.ts`; this pack
  only wires it. Three rules the wiring must keep:
  (1) **The `path` haystack is `${root}/${subfolder}`, not `fileSub(f)`.**
  `fileSub()` returns the bare subfolder, so passing it straight through drops
  the root and a keyword naming one silently matches nothing. `image_browser.py`
  builds the identical string (`f"{type_name}/{subfolder}"`, logical, NEVER the
  resolved OS path — that would put `home`/`<user>`/`comfyui` in every haystack)
  and `comfyui-gallery-loader` ports the same pair. A drift on any side means a
  file is hidden in one grid and plain in another.
  (2) **Server-side hiding is filtered ABOVE the newest-N cap**, inside
  `_probe_newest` — the one function that owns the cap — so a future call site
  cannot get the order wrong. That order is the whole reason hiding is a backend
  feature: filtering an already-truncated response answers a folder of 6000
  mostly-sensitive files with a near-empty grid. The pinned view is the one
  documented client-side exemption, for the same reason `narrowByKind` is:
  `/pins` has no cap to spend.
  (3) **A name escapes through THREE channels**, and CSS can only touch one.
  `setSpoilered` paints the visible text and removes the `title` (a native
  tooltip renders the name in full on hover regardless of any CSS); the
  **`aria-label` is the third** and is swapped in the markup, because an
  accessible name is not stylable. A test asserting the `title` is *empty*
  rather than *absent* passes against the bug.
  (4) **A `dc:subject` tag is TOKENIZED, never compared whole.** `safeTargetOf`
  passes `f.tags` straight to the kit, which does
  `for (const tag of target.tags ?? []) for (const t of tokenize(tag))`; the
  backend hands each tag to `is_safe_match` as its own `*parts` entry, which
  means the same thing. So `nsfw art` matches `nsfw` and `assets` still does not
  match `ass`. A whole-tag `===` would pass every positive test and make this
  pack disagree with `comfyui-gallery-loader` over the same bytes on the same
  disk. An ABSENT `tags` (an older backend) reads as "no keywords", NOT as an
  unknown to fail safe on — the four-state trap below belongs to `prompt_match`
  alone, and blurring every card against an older backend is indistinguishable
  from the feature being broken.
  (5) **The `🙈` control is a WRITE and rides the per-card `canWriteFile(f)`
  mirror**, so it never renders on the browse…/path tab — `/image_browser/tag`
  rejects `type=path` like every other write, and a control that 400s is worse
  than no control. It writes the user's FIRST configured keyword and is not
  rendered at all when the list is empty; there is no packaged fallback, because
  writing `nsfw` into a file whose owner filters on something else produces a
  file that says "marked" and is not hidden. The repaint uses the keywords the
  **server read back**, never the optimistic local guess — those differ whenever
  the write did not land the way the tap assumed, and painting the guess shows a
  mark the file does not carry which the next `/list` then silently corrects.
  (6) **The prompt tier has FOUR states and the last two must not collapse.**
  `true` / `false` are a cached verdict; `"unscanned"` means the file
  participates but has none yet and is read as SENSITIVE (the fail-safe
  direction for an unknown); an **absent** `promptMatch` means the target is
  outside the tier and is never sensitive by it. Defaulting the absent case in
  either direction is a shipped bug — `?? "unscanned"` blurs every folder card
  and every unreadable container the moment the tier comes on, and treating
  `"unscanned"` as `false` shows a sensitive render in the clear on a cold
  cache. `safeTargetOf()` passes `f.prompt_match` straight through, including
  when it is undefined, and both directions are pinned in
  `tests/js/safe-view.test.js` and `tests/test_helpers.py`. The pinned view is a
  documented non-participant (its `/pins` rows carry no verdict), the same
  exemption `narrowByKind` and the client-side hide already take.
- **Additive only.** Never clobber an existing tooltip/control; fall back to
  the native widget when there's no match. Never fabricate data.
- **Launcher API is version-sensitive.** The modal opens from `registerExtension`'s `actionBarButtons` / `commands` / `menuCommands`. If a future frontend renames or drops one, keep at least one launcher (button OR command) wired so the modal stays reachable.
- **Never hand-edit `CHANGELOG.md` or the `version` field** — release-please
  owns them (conventional commits drive the bump).

## Dev workflow

```sh
uv sync --group dev          # ruff, pytest, pre-commit
bun install                  # TypeScript, Biome, Vitest, knip, @laurigates/comfy-modal-kit (inlined at build)
pre-commit install
just check                   # typecheck + build + lint + test + test-e2e — the local CI gate
```

Two test environments, and the split is load-bearing:

```sh
bun run test                 # Vitest/jsdom (tests/js/) — no layout engine
just test-e2e                # builds, then Playwright/Chromium (tests/e2e/)
bun run test:e2e             # the browser suite alone (serves the CURRENT web/dist — build first)
bun run test:e2e:headed      # same, with a visible browser
```

`tests/js/` cannot fail for anything layout-dependent: jsdom accepts
`scrollTop = 500` on a zero-height scroller and reads it back verbatim, detached
or not. Scroll, clamping and lazy-load behaviour therefore only get asserted in
`tests/e2e/` — Chromium-only, so iOS momentum scrolling stays uncovered.

Iterating on the frontend needs a **`bun run build`** (the served file is
`web/dist/index.js`, not the source) plus a browser hard-refresh — no ComfyUI
restart. Changes to `image_browser.py` (backend) DO require a ComfyUI restart.

## Verify the frontend API against the sourcemap

The ComfyUI frontend (`comfyui-frontend-package`) ships **minified** — property
and method names are renamed in the bundle, so reading the running app's objects
by guessed names (or trusting old tutorials) is unreliable. The TypeScript types
from `@comfyorg/comfyui-frontend-types` cover `ComfyApp` but **not** the internal
`LGraphNode` / `LGraphCanvas` / widget interfaces (un-exported). Model the small
surface you touch with local structural interfaces, and verify the real shape
against the bundled sourcemap before coding against a LiteGraph / canvas API.

LiteGraph is bundled in the **`api-*.js.map`** chunk under
`.venv/lib/python*/site-packages/comfyui_frontend_package/static/assets/`. The
`.js.map` embeds the original TypeScript in `sourcesContent` — grep that, not the
minified `.js`:

```sh
cd .venv/lib/python*/site-packages/comfyui_frontend_package/static/assets
grep -l 'LGraphGroup' *.js.map        # find the chunk
```

Facts worth confirming this way (recheck on a `comfyui-frontend-package` bump):
`LiteGraph.NODE_TITLE_HEIGHT` (30); `canvas.selectedItems` is a
`Set<Positionable>` holding nodes + groups + reroutes; `canvas.selected_nodes` is
a node-only dictionary; canvas zoom is **wheel-driven**
(`processMouseWheel -> ds.changeScale`).

Two gotchas that follow: discriminate selected items by **shape, not
`instanceof`** (the class is renamed under minification); and to suppress native
zoom during a gesture, intercept `wheel` (capture, `passive:false`,
`preventDefault`), not just pointer events. Record what you confirm in a
"Verified frontend API" table above so the next change doesn't re-derive it.
